# Yacc Parser + Lex Scanner — Beginner-to-Exam Guide

## What files are covered?

This guide is based on the three supplied files:

- `parser.y` — the Yacc grammar and parser program.
- `lexer.l` — the Lex scanner that turns input text into tokens.
- `input(3).txt` — the test input to be checked.

The input supplied is:

```java
for (int i = +1: i<10 ; ++i} {
    boolean flag = true && false;
    double result = -5.5 + i - 2;
    flag = !flag || (i > 0);
    i--;
}
```

**Important observation:** The test input contains `:` where the `for` loop needs a semicolon, and `}` where the update section should be followed by `)`. Therefore, this test input is syntactically invalid for the grammar in `parser.y`. The parser should reject it. This guide explains the supplied program as written and does not silently fix the test case.

## 1. First understand the big picture

Think of the program as two workers:

```text
Input file (characters)
        |
        v
LEX SCANNER (lexer.l)
Turns character sequences into tokens
Examples: "for" -> FOR, "i" -> IDENTIFIER, "<" -> RELOP
        |
        v
YACC PARSER (parser.y)
Checks whether the token sequence follows the grammar
        |
        +---- valid token structure ----> Correct: the for loop is syntactically correct.
        |
        +---- invalid token structure --> Not correct: syntax error at line ...
```

**Lex recognizes the pieces. Yacc checks how the pieces fit together.**

- Lex does not decide whether the whole loop is grammatically correct.
- Yacc does not normally scan raw characters itself; it requests tokens from `yylex()`.
- `yyparse()` is the parser function generated by Yacc.

## 2. Basic Yacc syntax from zero

A Yacc file has three sections separated by `%%`:

```yacc
%{
/* C declarations and header files */
%}

/* Yacc declarations: tokens, precedence, types, etc. */

%%
/* Grammar rules */
%%
/* Supporting C functions, such as yyerror() and main() */
```

### Section 1 — C declarations

```yacc
%{
#include <stdio.h>
int yylex(void);
void yyerror(const char *s);
%}
```

Code inside `%{ ... %}` is copied into the generated C file.

- `#include <stdio.h>` provides standard input/output declarations such as `printf()`.
- `int yylex(void);` tells C that the Lex scanner function exists and returns an integer token code.
- `void yyerror(const char *s);` declares the function Yacc calls when it reports a syntax error.

In the supplied file, this section also declares `yyin`, `yytext`, `yylineno`, and `at_eof`, plus an integer called `err_line`.

### Section 2 — declarations

```yacc
%token FOR INT IDENTIFIER NUMBER
```

`%token` declares token names that the lexer can return and the parser can recognize.

For example, the lexer reads the characters `for` and returns `FOR`. It reads `i` and returns `IDENTIFIER`.

The supplied parser declares these token groups:

- Keywords/data types: `FOR`, `INT`, `DOUBLE`, `BOOLEAN_TYPE`
- Values/names: `IDENTIFIER`, `NUMBER`, `BOOLEAN`
- Punctuation: `LP`, `RP`, `LB`, `RB`, `SEMI`
- Assignment and signs: `ASSIGN`, `UPLUS`, `UMINUS`, `BPLUS`, `BMINUS`
- Increment/decrement: `PRE_INC`, `POST_INC`, `PRE_DEC`, `POST_DEC`
- Other operators: `RELOP`, `LOGICAL`, `NOT`, `UNKNOWN`

Token names are labels, not the original text. For example, both `<` and `>=` are returned as `RELOP`.

### Section 3 — grammar rules

Grammar rules describe the permitted order of tokens.

General form:

```yacc
rule_name : alternative_1
          | alternative_2
          ;
```

- The name on the left is a **nonterminal** (a grammar category).
- Names on the right can be tokens or other nonterminals.
- `:` means “is defined as”.
- `|` means “or”.
- `;` ends a grammar rule.
- An empty alternative means the category is allowed to contain nothing.

Example:

```yacc
type : INT | DOUBLE | BOOLEAN_TYPE ;
```

This means `type` can be `INT`, `DOUBLE`, or `BOOLEAN_TYPE`.

Example with an empty option:

```yacc
cond : | expr ;
```

This means the condition can be empty, or it can be an expression. The empty alternative is intentional and permits a form such as `for (init; ; update)`.

### Section 4 — supporting C code

The supplied file ends with:

```c
void yyerror(const char *s) {
    err_line = yylineno;
}
```

This records the current lexer line number when a syntax error is reported. It does not print the error itself.

Then `main()` opens the requested input file and calls `yyparse()`.

## 3. Essential Yacc vocabulary

| Term | Beginner-friendly meaning |
|---|---|
| Token | A labelled piece of input, such as `FOR` or `IDENTIFIER` |
| Terminal | A token that appears in the input stream |
| Nonterminal | A grammar category such as `expr`, `stmt`, or `for_stmt` |
| Production/rule | A definition such as `type : INT | DOUBLE ;` |
| Start symbol | The category from which parsing begins; here, `program` |
| `yyparse()` | Generated function that checks the token sequence against the grammar |
| `yylex()` | Scanner function generated from `lexer.l`; returns the next token |
| `yyerror()` | Error callback used when parsing fails |
| `yyin` | File pointer from which Lex reads input |
| `yylineno` | Line number maintained by Flex because `%option yylineno` is enabled |

**Remember:** `FOR` is a token; `for_stmt` is a grammar category.

## 4. Understand the supplied Lex file (`lexer.l`)

The parser depends on the lexer. The lexer rules tell Yacc what token each piece of text represents.

### 4.1 Header and options

```lex
%{
#include "y.tab.h"
int at_eof = 0;
%}
%option noyywrap yylineno
%s OP
```

- `#include "y.tab.h"` imports token definitions generated from the Yacc file, so the lexer can return `FOR`, `IDENTIFIER`, and the other token codes.
- `noyywrap` avoids needing a separate `yywrap()` function at end-of-file.
- `yylineno` tracks line numbers.
- `%s OP` declares the `OP` start condition used to classify `+`, `-`, `++`, and `--`.

### 4.2 Whitespace

```lex
[ \t\n\r]+ { }
```

Spaces, tabs, and line breaks are ignored.

### 4.3 Keywords and values

```lex
"for"                   { BEGIN(INITIAL); return FOR; }
"int"                   { BEGIN(INITIAL); return INT; }
"double"                { BEGIN(INITIAL); return DOUBLE; }
"boolean"               { BEGIN(INITIAL); return BOOLEAN_TYPE; }
"true"|"false"          { BEGIN(OP); return BOOLEAN; }
[0-9]+(\.[0-9]+)?       { BEGIN(OP); return NUMBER; }
[a-zA-Z_][a-zA-Z0-9_]*  { BEGIN(OP); return IDENTIFIER; }
```

The lexer returns token codes; it does not print token descriptions in this program.

- `for` → `FOR`
- `int` → `INT`
- `double` → `DOUBLE`
- `boolean` → `BOOLEAN_TYPE`
- `true` or `false` → `BOOLEAN`
- `10` or `5.5` → `NUMBER`
- `i`, `flag`, or `result` → `IDENTIFIER`

### 4.4 Operators and punctuation

- In state `INITIAL`, `++`, `--`, `+`, and `-` return `PRE_INC`, `PRE_DEC`, `UPLUS`, and `UMINUS`.
- In state `OP`, the same spellings return `POST_INC`, `POST_DEC`, `BPLUS`, and `BMINUS`, then switch back to `INITIAL`.
- `&&` and `||` return `LOGICAL`.
- `!` returns `NOT`.
- `<`, `<=`, `>`, `>=`, `==`, and `!=` return `RELOP`.
- `=` returns `ASSIGN`.
- `(`, `)`, `{`, `}`, and `;` return `LP`, `RP`, `LB`, `RB`, and `SEMI`.
- Any otherwise unmatched single character returns `UNKNOWN`.

The scanner's `INITIAL`/`OP` logic is a simple heuristic for classifying unary/binary and prefix/postfix operators, not a complete Java-language analysis.

## 5. Walk through every grammar rule in `parser.y`

### 5.1 The start of the grammar

```yacc
program : for_stmt ;
```

The whole input must match one `for_stmt`. There is no rule here allowing arbitrary extra text before or after the loop.

### 5.2 The main `for` loop

```yacc
for_stmt : FOR LP init SEMI cond SEMI upd RP stmt ;
```

Read this from left to right:

```text
FOR -> LP -> init -> SEMI -> cond -> SEMI -> upd -> RP -> stmt
```

In familiar code, the structure is:

```c
for ( initialization ; condition ; update )
    statement
```

Token mapping:

- `FOR` = `for`
- `LP` = `(`
- `init` = initialization part
- first `SEMI` = first `;`
- `cond` = condition
- second `SEMI` = second `;`
- `upd` = update part
- `RP` = `)`
- `stmt` = loop body

**This exact order is why the `:` in your test input causes a syntax error:** the grammar requires `SEMI` after `init`, but the lexer returns `UNKNOWN` for `:`.

### 5.3 Initialization

```yacc
init : | type IDENTIFIER ASSIGN expr | IDENTIFIER ASSIGN expr ;
```

There are three choices:

1. Empty initialization.
2. A declaration with assignment, such as `int i = +1`.
3. An assignment to an existing identifier, such as `i = 1`.

`type` means one of the recognized data types. `expr` means a valid expression.

Notice that this grammar does not include a declaration without assignment in the loop initializer, such as `int i;`.

### 5.4 Condition

```yacc
cond : | expr ;
```

The condition can be empty or be an expression, such as `i < 10`.

### 5.5 Update section

```yacc
upd : | update ;
```

The update part can be empty or match an `update`.

```yacc
update : PRE_INC IDENTIFIER | PRE_DEC IDENTIFIER
       | IDENTIFIER POST_INC | IDENTIFIER POST_DEC
       | IDENTIFIER ASSIGN expr ;
```

This accepts these patterns:

- `++i`
- `--i`
- `i++`
- `i--`
- `i = expression`

The grammar relies on the lexer to distinguish `PRE_INC` from `POST_INC`, and similarly for decrement.

### 5.6 Statements and blocks

```yacc
stmt : for_stmt | LB stmts RB | simple SEMI | SEMI ;
stmts : | stmts stmt ;
```

A statement may be:

- Another `for` loop (nested loop).
- A block surrounded by `{` and `}`.
- A simple statement followed by `;`.
- An empty statement `;`.

`stmts` means zero or more statements. The recursive alternative `stmts stmt` adds another statement to the block.

### 5.7 Simple statements

```yacc
simple : update | type IDENTIFIER | type IDENTIFIER ASSIGN expr ;
```

This accepts:

- An update such as `i--`.
- A declaration such as `boolean flag`.
- A declaration with initialization such as `double result = -5.5 + i - 2`.

The semicolon is supplied by the surrounding `stmt` rule: `stmt : simple SEMI`.

### 5.8 Data types

```yacc
type : INT | DOUBLE | BOOLEAN_TYPE ;
```

Only `int`, `double`, and `boolean` are recognized as types in this grammar.

### 5.9 Expressions: from broad to small

```yacc
expr  : logic ;
logic : rel | logic LOGICAL rel ;
rel   : arith | arith RELOP arith ;
arith : term | arith BPLUS term | arith BMINUS term ;
term  : IDENTIFIER | NUMBER | BOOLEAN
      | UPLUS term | UMINUS term | NOT term | LP expr RP ;
```

This is the expression grammar. Understand it from the bottom upward.

**`term` — the smallest expression pieces**

A term can be an identifier, number, Boolean literal, unary plus/minus, logical NOT, or a parenthesized expression.

Examples:
- `i`
- `10`
- `true`
- `+1`
- `-5.5`
- `!flag`
- `(i > 0)` — parentheses contain an `expr`

**`arith` — arithmetic expressions**

A `term` can be extended with `+ term` or `- term`.

Examples:
- `5.5 + i`
- `5.5 + i - 2`

The left-recursive form `arith : arith BPLUS term` allows a chain of additions. The equivalent applies to subtraction.

**`rel` — relational expressions**

An arithmetic expression can be compared with another arithmetic expression using `RELOP`.

Examples:
- `i < 10`
- `i > 0`
- `i <= 10`

**`logic` — logical expressions**

A relational expression can be joined with another relational expression using `&&` or `||`, represented by `LOGICAL`.

Example:
- `i < 10 && flag`

This grammar's exact structure has limitations: it allows `logic LOGICAL rel`, so logical operators combine `rel` categories, not arbitrary `logic` on the right. It also does not define precedence declarations (`%left`, `%right`, `%nonassoc`); do not claim it implements the full Java operator-precedence system.

**`expr` — the top expression category**

`expr : logic` means every accepted expression starts through the `logic` category.

## 6. How `main()` runs the parser

Supplied code:

```c
int main(int argc, char *argv[]) {
    const char *file = argc > 1 ? argv[1] : "input.txt";
    yyin = fopen(file, "r");
    if (!yyin) { printf("Cannot open %s\n", file); return 1; }
    if (yyparse() == 0)
        printf("Correct: the for loop is syntactically correct.\n");
    else
        printf("Not correct: syntax error at line %d.\n", err_line);
    return 0;
}
```

Flow:

1. If a filename is supplied on the command line, use it; otherwise use `input.txt`.
2. `fopen()` opens the file for reading.
3. If opening fails, print an error and stop.
4. `yyparse()` asks the lexer for tokens and checks them against the grammar.
5. If `yyparse()` returns `0`, print the success message.
6. Otherwise, print the syntax-error message with `err_line`.
7. Return from `main()`.

The `yyerror()` function sets `err_line = yylineno`. Because `yyerror()` itself does not print `s`, the displayed error message comes from `main()` after `yyparse()` fails.

## 7. Trace the supplied test input

Supplied input:

```java
for (int i = +1: i<10 ; ++i} {
    boolean flag = true && false;
    double result = -5.5 + i - 2;
    flag = !flag || (i > 0);
    i--;
}
```

### First error: `:` instead of `;`

The parser expects:

```text
FOR LP init SEMI ...
```

The lexer sees `for`, `(`, `int`, `i`, `=`, `+`, `1`, then `:`.

The colon does not match a specific rule, so the lexer returns `UNKNOWN`. But at this point the parser requires `SEMI`, not `UNKNOWN`. Therefore parsing fails here.

### Second visible problem: `}` instead of `)`

The loop header also contains `++i}`. The grammar expects `RP` (`)`) after the update section. The input supplies `RB` (`}`) instead. This is another syntax problem, although the parser may stop at the first error and not report every error in the same run.

### Why the body looks reasonable but does not rescue the input

The later body includes declarations, Boolean expressions, arithmetic, logical NOT/OR, and `i--`, which the grammar has rules for. However, a valid body cannot compensate for an invalid loop header. Parsing must satisfy the grammar in sequence.

### Expected result

The supplied input should be rejected with a syntax-error message, not the `Correct` message. The precise line number shown depends on when the parser invokes `yyerror()` and the line counter state.

### For learning only: corrected header shape

The intended header structure appears to be:

```java
for (int i = +1; i < 10; ++i) {
```

This is an illustration of the grammar's required punctuation, not a replacement for your supplied test case. If you test a corrected input, the entire file must still fit the grammar.

## 9. How to write this in the exam

If asked to explain or write a Yacc parser for a `for` loop, use this order.

1. **Aim:** State that Yacc checks the syntax of a `for` loop using grammar productions.
2. **Lex/Yacc relationship:** Lex converts characters to tokens; Yacc checks the sequence of tokens.
3. **Yacc structure:** Explain declarations, `%token`, grammar rules between `%%`, and supporting C code after the second `%%`.
4. **Start rule:** Explain `program : for_stmt ;`.
5. **Main loop production:** Write and explain `for_stmt : FOR LP init SEMI cond SEMI upd RP stmt ;`.
6. **Sub-rules:** Explain `init`, `cond`, `upd`, `update`, `stmt`, `stmts`, `simple`, and `type`.
7. **Expression grammar:** Explain `term` first, then `arith`, then `rel`, then `logic`, then `expr`.
8. **Error handling:** Explain `yyerror()`, `yyparse()`, and the success/error messages.
9. **Test case:** Show that `:` is returned as `UNKNOWN` where `SEMI` is required, and `}` appears where `RP` is required.
10. **Conclusion:** State that the parser accepts only input matching its grammar, and the supplied test input is invalid.

## 11. Beginner revision questions

1. **What is Yacc?** A parser generator that checks whether tokens follow a grammar.
2. **What is Lex?** A scanner generator that recognizes patterns in input characters.
3. **What does `%token` do?** Declares token names used by grammar rules.
4. **What does `%%` mean?** It separates the sections of a Lex/Yacc source file.
5. **What is a production rule?** A definition of how a grammar category can be formed.
6. **What is `program` here?** The start category; it must match `for_stmt`.
7. **What does `yyparse()` do?** Parses the token stream.
8. **What does `yylex()` do?** Returns the next token from the input.
9. **What does `yyerror()` do here?** Records the current line number when a syntax error is reported.
10. **Why is the supplied test invalid?** `:` is used instead of the required first semicolon, and `}` appears where the closing `)` is required.
11. **What does `SEMI` represent?** The semicolon `;`.
12. **What does `expr : logic ;` mean?** An expression is defined through the `logic` category.

## 12. Final revision formula

Memorize this chain:

**Input file → `main()` → `yyparse()` → `yylex()` → tokens → grammar rules → `yyerror()` if invalid → print result**

And memorize the loop production:

```yacc
for_stmt : FOR LP init SEMI cond SEMI upd RP stmt ;
```

In plain English:

**`for` → `(` → initialization → `;` → condition → `;` → update → `)` → statement**

That one line is the backbone of this parser.
