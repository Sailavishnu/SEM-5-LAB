# Lex Program: Java `for` Loop Tokenizer — Exam Study Notes

## 1. What this program does

This Lex program reads a Java-like `for` loop and prints each piece as a **token**. It recognizes keywords, identifiers, numbers, booleans, operators, brackets, and semicolons. It does **not** execute the Java loop or calculate the values of variables. It only scans the input text and classifies its pieces.

The program is based on the supplied `for(1).l` and the supplied test input `input(2).txt`.

## 2. Test input supplied

```java
for (int i = +1; i <= 10; ++i) {
    boolean flag = true && false;
    double result = -5.5 + i - 2;
    flag = !flag || (i > 0);
    i--;
}
```

## 3. Main Lex concepts

### 3.1 Lex program structure

A Lex file has three sections separated by `%%`:

```lex
definitions
%%
rules
%%
user-defined C code
```

In this file:

1. **Definitions section**: C header, Lex options, start state, and regular-expression names.
2. **Rules section**: patterns and actions. When a pattern matches the input, its action runs.
3. **User-code section**: `main()` starts the scanner by calling `yylex()`.

### 3.2 C header block: `%{ ... %}`

```lex
%{
#include <stdio.h>
%}
```

Code inside `%{ ... %}` is copied into the generated C source. `stdio.h` is needed for `printf()`.

### 3.3 `%option noyywrap`

```lex
%option noyywrap
```

This tells Lex/Flex not to call `yywrap()` at the end of input. It avoids needing to write a separate `yywrap()` function for this simple program.

### 3.4 Start condition: `%s OP`

```lex
%s OP
```

This declares an inclusive start condition named `OP`. The program uses two scanner states:

- `INITIAL`: the normal starting state.
- `OP`: a state used to help decide how `+`, `-`, `++`, and `--` should be labelled.

`BEGIN(INITIAL)` switches to the normal state. `BEGIN(OP)` switches to the `OP` state.

**Important:** This is a simple heuristic, not a full Java parser. The state is not a complete or always-correct way to determine whether an operator is unary, binary, prefix, or postfix.

### 3.5 Named regular expressions

```lex
DIGIT   [0-9]
NUMBER  {DIGIT}+(\.{DIGIT}+)?
ID      [a-zA-Z_][a-zA-Z0-9_]*
```

- `DIGIT [0-9]`: one decimal digit.
- `NUMBER`: one or more digits, optionally followed by a decimal point and one or more digits. Examples: `1`, `10`, `5.5`.
- `ID`: starts with an English letter or underscore; later characters can be letters, digits, or underscores. Examples: `i`, `flag`, `result`.

`{DIGIT}` and `{NUMBER}` reuse named patterns. The supplied number pattern does not cover every numeric format in Java (for example, negative signs are handled separately as operators).

## 4. How Lex scans the input

Lex scans the input from left to right. It chooses the longest matching pattern; if multiple rules match the same longest text, rule order decides the tie. The action attached to the selected rule runs.

For example, `<=` should be matched as one relational operator, not as `<` followed by `=`. Likewise, `++` is matched as a two-character operator rather than two `+` tokens.

Whitespace is matched by `[ \t\n\r]+` and ignored, so it produces no output. The scanner still processes the non-whitespace characters in order.

## 5. Understand every rule group

### 5.1 Ignore whitespace

```lex
[ \t\n\r]+ { }
```

Matches spaces, tabs, line feeds, and carriage returns. The empty action discards them.

### 5.2 Keywords

```lex
"for"     { BEGIN(INITIAL); printf("< keyword : for >\n"); }
"int"     { BEGIN(INITIAL); printf("< keyword : int >\n"); }
"double"  { BEGIN(INITIAL); printf("< keyword : double >\n"); }
"boolean" { BEGIN(INITIAL); printf("< keyword : boolean >\n"); }
```

These exact words are labelled as keywords. In the supplied test, they recognize `for`, `int`, `boolean`, and `double`.

### 5.3 Boolean literals

```lex
"true"|"false" {
    BEGIN(OP);
    printf("< boolean : %s >\n", yytext);
}
```

Matches either boolean literal. `yytext` contains the text matched, so the output prints `true` or `false`.

### 5.4 Numbers and identifiers

```lex
{NUMBER} { BEGIN(OP); printf("< number : %s >\n", yytext); }
{ID}     { BEGIN(OP); printf("< identifier : %s >\n", yytext); }
```

The number rule prints numeric tokens. The identifier rule prints variable names. For the test, identifiers include `i`, `flag`, and `result`.

### 5.5 `+`, `-`, `++`, and `--` in `INITIAL`

```lex
<INITIAL>"++" { printf("< pre-increment : ++ >\n"); }
<INITIAL>"--" { printf("< pre-decrement : -- >\n"); }
<INITIAL>"+"  { printf("< unary plus : + >\n"); }
<INITIAL>"-"  { printf("< unary minus : - >\n"); }
```

When the scanner is in `INITIAL`, these rules label the operators as prefix/unary forms. Notice that these actions do not switch the state.

### 5.6 `+`, `-`, `++`, and `--` in `OP`

```lex
<OP>"++" { BEGIN(INITIAL); printf("< post-increment : ++ >\n"); }
<OP>"--" { BEGIN(INITIAL); printf("< post-decrement : -- >\n"); }
<OP>"+"  { BEGIN(INITIAL); printf("< binary plus : + >\n"); }
<OP>"-"  { BEGIN(INITIAL); printf("< binary minus : - >\n"); }
```

When in `OP`, these operators are labelled as postfix/binary forms, and the scanner switches back to `INITIAL`.

### 5.7 Arithmetic operators

```lex
"*" { BEGIN(INITIAL); printf("< multiplication : * >\n"); }
"/" { BEGIN(INITIAL); printf("< division : / >\n"); }
```

Recognizes multiplication and division.

### 5.8 Relational operators

```lex
"<="|">="|"=="|"!="|"<"|">" {
    BEGIN(INITIAL);
    printf("< relational operator : %s >\n", yytext);
}
```

Recognizes less than, greater than, less-than-or-equal, greater-than-or-equal, equality, and inequality.

### 5.9 Logical operators

```lex
"&&"|"||" { BEGIN(INITIAL); printf("< logical operator : %s >\n", yytext); }
"!"       { BEGIN(INITIAL); printf("< logical NOT : ! >\n"); }
```

`&&` means logical AND, `||` means logical OR, and `!` means logical NOT.

### 5.10 Assignment

```lex
"=" { BEGIN(INITIAL); printf("< assignment : = >\n"); }
```

Recognizes the assignment operator. It is different from `==`, which is a relational equality operator. Lex's longest-match rule helps `==` be matched as a single token.

### 5.11 Parentheses, braces, and semicolon

The rules recognize `(`, `)`, `{`, `}`, and `;` and print a descriptive token for each.

A key detail in this program:
- `(` switches to `INITIAL`.
- `)` switches to `OP`.
- `{`, `}`, and `;` switch to `INITIAL`.

These state changes affect how later `+`, `-`, `++`, and `--` tokens are labelled.

### 5.12 Unknown characters

```lex
. { printf("< unknown : %s >\n", yytext); }
```

If no earlier rule matches a character, this rule prints it as unknown. A dot in a Lex pattern matches one character other than a newline in the usual Flex behavior.

## 6. What `yytext`, `yylex()`, `BEGIN()`, and `printf()` mean

- `yytext`: the text matched by the current Lex rule.
- `yylex()`: runs the scanner and processes input using the rules.
- `BEGIN(state)`: changes the scanner's start condition.
- `printf()`: prints the token label to the screen.
- `main()`: prints the prompt, initializes the scanner state, calls `yylex()`, then returns.

The `main()` in the supplied program is:

```c
int main(void)
{
    printf("Enter Java for loop:\n");
    BEGIN(INITIAL);
    yylex();
    return 0;
}
```

### Why does the program call `++i` “pre-increment” here?

The `++` occurs after the second semicolon. The scanner is in `INITIAL` at that point, so the `<INITIAL>"++"` rule labels it as `pre-increment`. This happens to match the source text `++i`.

### Important limitation in the supplied rules

The state heuristic can misclassify some expressions. For example, after a `)` the program switches to `OP`, so a `+` immediately following a closing parenthesis could be labelled binary even when the intended context is unary. Also, the program recognizes only the listed keywords and operators; it is not a complete Java lexer. In an exam, explain the behavior of the code as written rather than claiming it fully parses Java.

## 8. Exam writing flow: how to present this program

Use this order if asked to explain the program or write its algorithm.

1. **Aim:** State that the program uses Lex to identify tokens in a Java-like `for` loop.
2. **Structure:** Explain the three sections separated by `%%`.
3. **Definitions:** Mention `stdio.h`, `%option noyywrap`, `%s OP`, and the `DIGIT`, `NUMBER`, and `ID` patterns.
4. **Whitespace:** Explain that spaces, tabs, and newlines are ignored.
5. **Token rules:** Explain keywords, booleans, numbers, identifiers, arithmetic operators, relational operators, logical operators, assignment, delimiters, and unknown characters.
6. **State logic:** Explain `INITIAL` versus `OP`, and how `BEGIN()` switches states to label `+`, `-`, `++`, and `--`.
7. **Output:** Explain that `yytext` contains the matched token and `printf()` prints its category.
8. **Main:** Explain that `main()` initializes `INITIAL` and calls `yylex()`.
9. **Test case:** Show a few representative tokens from the given input, then mention that the remaining tokens are processed in the same left-to-right manner.
10. **Conclusion:** The program performs lexical analysis; it classifies tokens but does not execute the Java statements.

## 10. Quick revision questions

1. **What is Lex used for here?** To scan input and classify tokens.
2. **What is `yytext`?** The currently matched text.
3. **What does `yylex()` do?** Runs the lexical scanner.
4. **Why ignore whitespace?** Spaces and line breaks do not need token output.
5. **Why list `<=` and `++` as complete patterns?** They should be recognized as two-character tokens.
6. **What is `BEGIN(OP)`?** A switch to the `OP` scanner state.
7. **Does the program execute the loop?** No; it only tokenizes the text.
8. **What does `.` do in the final rule?** It catches otherwise unmatched single characters (except newline in typical Flex behavior).
9. **Difference between `=` and `==`?** Assignment versus equality comparison.
10. **What should you mention as a limitation?** The `INITIAL`/`OP` state heuristic is simple and is not a full Java parser.

## 11. Final exam tip

Memorize the **flow**, not every `printf()` line:

**Definitions → Ignore whitespace → Match token category → Print token → Change state when required → Continue scanning → `main()` starts `yylex()`**

When writing the answer, include a few examples from the supplied test (`for`, `i`, `+1`, `<=`, `true`, `&&`, `-5.5`, `!`, `||`, `--`). That demonstrates that you understand both the rules and their output.
